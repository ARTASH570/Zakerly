# Zakerly

منصة تجمع المعلمين بطلابهم: فيديوهات محمية، متابعة أداء، ومدفوعات إلكترونية.

## الهيكل الحالي

```
zakerly/
├── app/
│   ├── page.tsx              # صفحة الهبوط
│   ├── login/page.tsx        # تسجيل الدخول (معلم/طالب)
│   ├── teacher/dashboard/    # داشبورد المعلم (هيكل مبدئي)
│   ├── student/dashboard/    # داشبورد الطالب (هيكل مبدئي)
│   └── globals.css
├── lib/
│   └── supabaseClient.ts     # الاتصال بـ Supabase
├── supabase/
│   └── schema.sql            # مخطط قاعدة البيانات كامل بالجداول والحماية (RLS)
└── .env.local.example        # المتغيرات المطلوبة
```

## خطوات التشغيل

1. **اعمل مشروع على Supabase** (supabase.com) وخد الـ URL والـ anon key
2. **شغّل ملف `supabase/schema.sql`** في SQL Editor بتاع Supabase - ده هيعمل كل الجداول (معلمين، طلاب، كورسات، فيديوهات، مدفوعات، اشتراكات، تقييمات) مع الحماية (Row Level Security) اللي بتضمن كل معلم يشوف بياناته بس وكل طالب يشوف بياناته بس
3. **انسخ `.env.local.example` لـ `.env.local`** واملأ القيم
4. **ثبّت المكتبات:**
   ```
   npm install
   ```
5. **شغّل المشروع محليًا:**
   ```
   npm run dev
   ```

## نظام الدفع (Paymob + Stripe) ✅ جاهز

**الفكرة:** كل مدفوعات الطلاب بتيجي لحسابك انت (Paymob للمصريين/المنطقة، Stripe للدوليين)،
وبعدين انت بتحوّل نصيب كل معلم يدويًا آخر الشهر (زي ما اتفقنا). كل الفلوس بتتسجل في جدول `payments`.

### الملفات:
- `lib/paymob.ts` + `lib/stripe.ts` — الاتصال بكل بوابة
- `app/api/payments/paymob/create` و `app/api/payments/stripe/create` — بدء عملية الدفع
- `app/api/payments/paymob/webhook` و `app/api/payments/stripe/webhook` — استقبال تأكيد الدفع وتفعيل الاشتراك أوتوماتيك
- `components/PaymentButton.tsx` — الزرار اللي بيستخدمه الطالب

### خطوات التفعيل:
1. **Paymob**: من الـ Dashboard خد الـ Secret Key والـ Public Key (Settings > Payment Integrations)، والـ Integration ID، والـ HMAC Secret (من صفحة الـ iFrame/Integration)
2. **سجّل رابط الـ webhook عند Paymob**: `https://yourdomain.com/api/payments/paymob/webhook` في إعدادات الـ Integration
3. **Stripe**: خد الـ Secret Key من dashboard.stripe.com، وسجّل webhook على `https://yourdomain.com/api/payments/stripe/webhook` مع حدث `checkout.session.completed`
4. **للتجربة محليًا**: استخدم Stripe CLI (`stripe listen --forward-to localhost:3000/api/payments/stripe/webhook`) لأن الـ webhook محتاج رابط عام يشوفه Stripe

### ⚠️ ملاحظة مهمة
سعر الكورس بالدولار في Stripe محسوب حاليًا بافتراض إنه نفس رقم السعر بالجنيه (تحويل 1:1 مؤقت في الكود) —
لازم تعدّل `priceUsdCents` في `app/api/payments/stripe/create/route.ts` بسعر صرف حقيقي أو تحدد سعر بالدولار منفصل لكل كورس.

## Bunny Stream (رفع وتشغيل الفيديوهات) ✅ جاهز

**الفكرة الأمنية:** الفيديو بيترفع مباشرة من متصفح المعلم لـ Bunny (من غير ما يعدي على سيرفرنا،
أسرع وأرخص). ولما الطالب يحاول يشوف فيديو، السيرفر بيتأكد الأول إنه مشترك ودافع فعلاً،
وبعدين بس بيديله رابط مشاهدة **موقّع** وصالح لمدة ساعتين بس — ده اللي بيمنع أي حد يشارك اللينك.

### الملفات:
- `lib/bunny.ts` — إنشاء فيديو، تجهيز بيانات الرفع الآمن (TUS)، وتوليد رابط مشاهدة موقّع
- `app/api/videos/create` — المعلم يبدأ رفع فيديو جديد لكورسه
- `app/api/videos/playback` — بيتأكد إن الطالب مشترك قبل ما يديله رابط المشاهدة
- `components/VideoUploader.tsx` — واجهة رفع الفيديو للمعلم (مع progress bar)
- `components/VideoPlayer.tsx` — مشغل الفيديو للطالب
- `app/teacher/courses/` — المعلم بيضيف كورس ويدير فيديوهاته
- `app/student/courses/[id]/watch/` — الطالب المشترك يشوف فيديوهات الكورس

### خطوات التفعيل:
1. اعمل حساب على bunny.net وأنشئ **Video Library** جديدة
2. من تبويب **API** بالمكتبة: خد الـ Library ID والـ API Key
3. من تبويب **Security**: فعّل **Embed View Token Authentication**، وخد الـ **Token Authentication Key**
4. حط القيم دي في `.env.local`

### ✅ الأمان
الـ endpoints دي بقت متحققة فعليًا من هوية المستخدم (شوف قسم "التحقق الحقيقي من الهوية" تحت) —
مبقاش ممكن حد ينتحل شخصية معلم أو طالب تاني.

## نظام الدفع الكامل: Paymob + Stripe + PayPal ✅ جاهز

**الاستراتيجية:**
- **مصر والخليج** → Paymob (يغطي مصر، السعودية، عمان، الإمارات ببوابة واحدة)
- **أمريكا وأوروبا (دولي)** → الطالب يختار بين **PayPal** (الأبسط، من غير أي التزام ضريبي عليك كـ Merchant of Record) أو **Stripe** (دفع بالبطاقة مباشرة)

### ملفات PayPal الجديدة:
- `lib/paypal.ts` — إنشاء طلب دفع (Order) وتأكيده (Capture)
- `app/api/payments/paypal/create` — بدء الدفع
- `app/api/payments/paypal/capture` — تأكيد الدفع بعد موافقة الطالب على PayPal وتفعيل اشتراكه
- `app/student/paypal/return` — الصفحة اللي PayPal بيرجّع الطالب ليها بعد الموافقة

### خطوات التفعيل:
1. اعمل حساب Business على paypal.com
2. من developer.paypal.com اعمل App وخد الـ Client ID والـ Secret
3. ابدأ بـ `PAYPAL_MODE=sandbox` للتجربة، وغيّرها لـ `live` لما تبقى جاهز فعليًا

### ⚠️ الفرق التقني بين PayPal وباقي البوابات
PayPal (وكذلك Stripe checkout) بيشتغلوا بنظام "Redirect + Return" مش "Webhook فوري بس" —
يعني الطالب بيتحول لصفحة PayPal، يوافق، وبعدين بيرجع لموقعنا (`/student/paypal/return`)
واحنا في اللحظة دي بنأكد الدفع فعليًا (Capture) ونفعّل الاشتراك. ده معناه إن التفعيل بيحصل
فورًا وقت رجوع الطالب، مش لازم تستنى webhook منفصل زي Paymob وStripe.

— **لو كنت شغّلت الملف قبل كده، لازم تشغّله تاني.**

### ✅ اتصلح بالكامل (كود فعلي، مش بس اقتراحات)
- **تقوية كلمة السر**: 8 أحرف كحد أدنى بدل 6
- **Security Headers** (`next.config.js`): حماية من clickjacking وmime-sniffing وتسريب الـ referrer
- **التحقق من صحة البيانات (Zod)** — `lib/validation.ts`: كل الـ API routes الحساسة (الدفع، رفع الفيديو،
  المشاهدة) بقت بتتحقق من شكل البيانات فعليًا (UUID صحيح، نص بطول منطقي، رقم موجب) مش بس "موجود ولا لأ"
- **Rate Limiting حقيقي بـ Upstash Redis** — `lib/rateLimit.ts`: دقيق حتى لو Vercel شغّل نسخ متعددة
  من السيرفر بالتوازي (النسخة القديمة في الذاكرة كانت بتتفلت في الحالة دي). لو Upstash مش متظبط
  بعد، بيرجع تلقائيًا لنسخة الذاكرة البسيطة (كويسة للتطوير المحلي بس، مش للإنتاج)
- **مراقبة الأخطاء (Sentry)** — `sentry.*.config.ts` + `instrumentation.ts`: أي خطأ يحصل لمستخدم حقيقي
  (فشل دفع، فشل رفع فيديو) هتشوفه في لوحة تحكم Sentry فورًا بدل ما تعرفه من شكوى المستخدم
- **حد أقصى لحجم الفيديو المرفوع**: 2 جيجا للفيديو الواحد، بيترفض من المتصفح قبل ما يبدأ الرفع أصلًا

### خطوات التفعيل للأدوات الجديدة:
1. **Upstash**: اعمل حساب على upstash.com (فيه خطة مجانية سخية)، اعمل Redis Database، وخد الـ REST URL والـ Token
2. **Sentry**: اعمل حساب على sentry.io، اعمل مشروع Next.js، وخد الـ DSN + اسم المؤسسة والمشروع

### 🟡 مش كود - دول إعدادات من لوحة تحكم Supabase وBunny نفسهم

**1. تفعيل تأكيد الإيميل (يمنع حسابات وهمية):**
- روح لـ Supabase Dashboard → Authentication → Providers → Email
- فعّل **"Confirm email"**
- (اختياري لكن موصى بيه) فعّل **"Leaked password protection"** من نفس الصفحة تقريبًا، بيمنع المستخدم يستخدم كلمة سر ظهرت في تسريبات بيانات معروفة

**2. حد أقصى لمدة الفيديو (حماية إضافية من التكلفة على Bunny):**
- روح لـ Bunny Dashboard → مكتبة الفيديو بتاعتك → Settings
- فيه خيار لتحديد أقصى مدة/جودة للفيديوهات المرفوعة، اضبطه حسب طول محاضراتك المعتاد

**3. تدوير الـ Service Role Key (لو ظهر بالغلط في أي مكان زي Git أو سكرين شير):**
- روح لـ Supabase Dashboard → Settings → API
- دوس **"Roll"** جنب الـ `service_role` key، وحدّث القيمة الجديدة في `.env.local` وفي إعدادات Vercel
- ده بيلغي أي نسخة قديمة اتسربت فورًا

## رد على مراجعة أمنية إضافية (4 نقاط)

### ✅ 1. كل الـ API routes بتتحقق من الصلاحيات مش بس الجلسة
`requireStudent()`/`requireTeacher()` (في `lib/auth.ts`) بيتأكدوا إن المستخدم عنده جلسة **وكمان**
إن دوره فعلاً طالب/معلم (موجود في الجدول المناسب). وبعد كده كل route بيتأكد من ملكية المورد نفسه:

### ✅ 2. روابط الفيديو - Token Authentication مفعّل من الأساس
`lib/bunny.ts` بيولّد رابط موقّع (HMAC token) بينتهي بعد ساعتين، مش رابط ثابت قابل للمشاركة.

### ✅ 3. الـ Webhooks بتتحقق من التوقيع — وضفنا واحد كان ناقص
Paymob (HMAC) وStripe (`constructEvent`) كانوا بيتحققوا من التوقيع من الأول. **PayPal كان
معتمد بس على رجوع الطالب لصفحتنا بعد الموافقة (من غير webhook منفصل)** - لو حصل عطل واتقفلت
الصفحة قبل ما ترجع، الفلوس كانت بتتاخد بس الاشتراك مش بيتفعل. ضفنا:
- `app/api/payments/paypal/webhook` - بيتحقق من التوقيع فعليًا عبر PayPal API نفسه قبل ما يصدّق أي حاجة
- محتاج تسجّل الـ webhook في PayPal Dashboard على `PAYMENT.CAPTURE.COMPLETED` وتحط `PAYPAL_WEBHOOK_ID` في `.env.local`

### 🔴 4. لقينا تسريب حقيقي في RLS واتصلح
كانت سياسة `teachers_public_select` بتسمح لأي حد يقرأ **الصف كامل** بتاع أي معلم عنده كورس منشور -
يعني رقم تليفونه وحالة اشتراكه (Trial/Active) كانوا متاحين لأي حد يعرف الـ anon key (وهو أصلاً ظاهر
للعامة في أي موقع Next.js). المشكلة إن RLS بيشتغل على مستوى **الصف**، مش العمود - فسياسة "تسمح
بالقراءة" بتفتح كل الأعمدة مش بس اللي بنعرضها في الواجهة.

**الحل:** شلنا السياسة العامة خالص، وعملنا **View منفصل** (`public_teacher_profiles`) بيعرض
`id, full_name, subject, bio` بس، وحدّثنا صفحات تصفح المعلمين تستخدمه بدل الجدول الأصلي.
**لازم تشغّل `schema.sql` تاني في Supabase عشان الإصلاح ده يتفعّل.**

## تنفيذ بنود "الأمان والبنية التحتية" (1-6 من طلب المراجعة الاحترافية)

### 1) مراجعة أمنية كاملة - أهم اكتشاف
**المشروع معندوش أصلاً صفحة "نسيت كلمة السر"** - يعني مستخدم نسي كلمة سره كان هيتقفل بره حسابه
نهائيًا من غير أي حل. اتبنت من الصفر (`/forgot-password`, `/reset-password`).
باقي المراجعة (Auth, Authorization, RLS, Bunny, Payments) كانت متغطية من الجولات اللي فاتت.

### 2) Rate Limiting احترافي - بقى شامل كل النقط المطلوبة
- **Login** (`/api/auth/login`): 5 محاولات/5 دقايق بالإيميل + 20/5 دقايق بالـ IP (منع brute-force)
- **Register** (`/api/auth/register`): 5 حسابات/ساعة لكل IP (منع إنشاء حسابات وهمية بالجملة)
- **Forgot Password** (`/api/auth/forgot-password`): 3 طلبات/ساعة (منع سبام إيميلات الاستعادة)
- **Reset Password** (`/api/auth/reset-password`): 5 محاولات/10 دقايق
- **Payments** و**Video Playback**: موجودين من قبل، وضفنا Rate Limit لمشاهدة الفيديو (كان الوحيد الناقص)

- **Indexes جديدة**: `sections_course_id_idx`, `videos_section_id_idx`, و`videos_course_id_idx`

- **تقدم الكورس**: نسبة مئوية وشريط تقدم على كل كارت كورس (فيديوهات مكتملة/الإجمالي)
- **الدرجات**: صفحة `/student/grades` - كل الدرجات والحضور مجمّعة حسب الكورس مع متوسط لكل واحد
- **سرعة التشغيل**: أزرار 0.75x/1x/1.25x/1.5x/2x تحت المشغل مباشرة (`player.setPlaybackRate` - جزء رسمي من API بتاعة player.js)
- **البحث داخل الكورس**: خانة بحث في صفحة المشاهدة بتفلتر قائمة الفيديوهات فورًا

### 🟡 مؤجل - محتاج بنية تحتية جديدة كليًا:
- **الوضع الداكن (Dark Mode)**: التصميم الحالي أصلًا Dark-only بتصميم "السبورة" - إضافة وضع فاتح
  محتاجة نظام ألوان تاني كامل يتطبق على كل صفحة في المشروع، مش تبديلة بسيطة
- **الشهادات**: محتاجة ميزة توليد PDF كاملة (مش موجودة خالص)
- **سجل الامتحانات**: مفيش ميزة "امتحانات" أصلًا في المشروع (بس تقييمات يدوية من المعلم)
- **الإشعارات**: هتيجي طبيعيًا مع "مركز الإشعارات" (بند منفصل لسه ما اتبناش)

## نظام الكويزات (مع توليد أسئلة بالـ AI) ✅ جاهز

### الفكرة
كويز مرتبط بكورس (واختياريًا بفيديو معين)، أسئلة اختيار من متعدد أو صح/غلط، تصحيح فوري
وأوتوماتيكي بالكامل على السيرفر (الطالب أبدًا مابيبعتش درجته بنفسه - التصحيح بيحصل بمقارنة
إجابته بعمود `is_correct` اللي محفوظ في الداتابيز، مش بأي حاجة جاية من المتصفح).

### جداول جديدة
`quizzes` · `quiz_questions` · `quiz_options` · `quiz_attempts` · `quiz_answers`
(شغّل `supabase/quiz_schema.sql` في Supabase SQL Editor بعد `schema.sql`)

### توليد الأسئلة بالـ AI
المعلم يلصق محتوى/ملخص الدرس في صفحة إدارة الكويز، ويختار عدد الأسئلة، والـ AI (Claude API)
بيرجع أسئلة مقترحة المعلم يراجعها ويختار اللي عايز يحفظه - مفيش حفظ تلقائي من غير مراجعة بشرية.

**⚠️ خطوة تفعيل مطلوبة:** ضيف `ANTHROPIC_API_KEY` في `.env.local` (المفتاح من
https://console.anthropic.com/settings/keys). من غيره زرار "اقترح أسئلة" هيرجع خطأ واضح
للمعلم، بس باقي النظام (الإضافة اليدوية، أخذ الكويز، التصحيح) بيشتغل عادي من غيره.

### الصفحات الجديدة
- المعلم: `/teacher/quizzes` (قائمة) و`/teacher/quizzes/[id]` (إدارة أسئلة + توليد AI + نشر)
- الطالب: `/student/quizzes` (قائمة الكويزات المتاحة) و`/student/quizzes/[id]` (أخذ الكويز والنتيجة)

### الأمان
- الطالب مايقدرش يشوف `is_correct` مباشرة من الداتابيز خالص (مفيش RLS policy select للطالب
  على `quiz_options`) - بياخد الأسئلة عن طريق `/api/student/quizzes/[id]` اللي بيشيل العمود ده
  قبل ما يرجع الرد
- التصحيح والدرجة بيتحسبوا وبيتحفظوا فقط عن طريق `/api/student/quizzes/attempts/[id]/submit`
  بالـ service role، مش عن طريق كتابة مباشرة من المتصفح
- عدد المحاولات المسموح بيه بيتفحص على السيرفر قبل أي محاولة جديدة

## ربط الكويزات بالفيديو + الدرجات + بحث موحد + إدارة الأدمنز ✅ جاهز

- **الكويز على الفيديو**: لو المعلم ربط كويز بفيديو معين، بيظهر بانر تلقائي تحت
  البلاير في صفحة المشاهدة (`/student/courses/[id]/watch`). كويزات الكورس العامة
  (اللي مش مرتبطة بفيديو معين) بتظهر في قايمة جانبية منفصلة
- **درجات الكويزات**: صفحة "درجاتي" (`/student/grades`) بقى فيها قسم "نتايج
  الكويزات" منفصل عن تقييمات المعلم اليدوية، بياخد بياناته من `quiz_attempts`
- **بحث موحد**: مربع البحث في أعلى داشبورد الطالب بقى شغال فعليًا - بيدور في
  الكورسات المنشورة وview بيانات المعلمين الآمنة (`public_teacher_profiles`)
  ويطلع نتايج لايف وهو بيكتب. الميزة دي (`components/dashboard/GlobalSearch.tsx`)
  اختيارية عن طريق prop اسمه `searchable` على `DashboardShell`، مفعّلة للطالب بس
  دلوقتي عشان محدش يكسر داشبورد المعلم أو الأدمن
- **إدارة الأدمنز** (`/admin/admins`): الأدمن يقدر يرقّي أي حساب معلم أو طالب
  مسجل بالفعل لأدمن بمجرد كتابة إيميله - من غير ما يفتح Supabase SQL Editor تاني.
  شغّل `supabase/admin_management_schema.sql` الأول (فيه function آمنة بتلاقي
  المستخدم بالإيميل من غير ما تكشف بيانات حساسة). ملحوظة: السكريبت القديم
  `create_first_admin.sql` لسه لازم يتشغل يدويًا **مرة واحدة بس** لأول أدمن على
  الإطلاق (مفيش أدمن أصلًا يرقّي حد قبل كده)
